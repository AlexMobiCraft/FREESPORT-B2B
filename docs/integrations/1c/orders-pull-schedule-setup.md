# Заказы сайта → 1С: вторая настройка БУС «По расписанию»

Регламент для администратора 1С. Настройка делается в 1С без правок кода сайта и расширения БУС.

## Зачем это нужно

В режиме БУС «В режиме реального времени» 1С выгружает на сайт только изменения каталога и **не забирает заказы**: процедура `ВыгрузкаВРеальномВремениВФоне` не вызывает загрузку документов (расширения 8.1.0.40 и 8.1.0.45 в этом совпадают). Заказы уходили в 1С только при ручном или плановом полном обмене (`mode=query` на проде: 03.11 и 05.11.2026).

Решение — две настройки обмена:

| Настройка | Режим | Назначение |
| --- | --- | --- |
| А (существующая) | «В режиме реального времени» | каталог, остатки, цены; **не трогать** |
| Б (новая) | «По расписанию», каждые 300 с | только загрузка заказов с сайта |

## Значения настройки Б

Основа — настройка А: форма настройки БУС копирование не поддерживает, поэтому реквизиты вносятся вручную. Значения ниже взяты из настройки А (скриншоты владельца).

**Общие параметры**

| Параметр | Значение |
| --- | --- |
| Только изменения | Да (иначе при включённой выгрузке заказов раз в 5 минут уйдут все заказы) |
| Выгрузка информации о номенклатуре, контрагентов, справочников | Нет |
| Обмен документами | Да |
| Порядок | Сперва БУС, затем 1С |
| Деактивировать товары | Нет |

**Документы**

| Параметр | Значение |
| --- | --- |
| Загружать заказы | Да |
| Загружаются с | 01.01.2025 |
| Обновлять документы 1С по данным сайта | Да |
| Ручная скидка | Нет |
| Номенклатура доставки | пусто |
| Выгружать заказы | Нет |
| Соответствие статусов | пусто |

**Реквизиты документа «Заказ клиента»**

| Реквизит | Значение |
| --- | --- |
| Дата документов | «С сайта» |
| Нумерация | «Автоматически» |
| Режим записи | «Проводить не оперативно» |
| Отменённые | «Помечать на удаление» |
| Организация | «Сопоставление по свойству документа», значение «Организация» |
| Склад | «Сопоставление по свойству документа», значение «Склад» |
| Соглашение | «Фиксированное значение» — «Стандартное» |
| Ответственный, Банковский счёт, Менеджер, Подразделение | «Предопределённый алгоритм» |

**Загрузка контрагентов**

| Параметр | Значение |
| --- | --- |
| Обновлять контрагентов в 1С | Да |
| ФИО в полное наименование физлиц | Нет |
| Контрагент, Соглашение физлица, Группа для новых партнёров | пусто |

**Сверить с настройкой А рядом** (значения здесь не приводятся, чтобы не ошибиться): форма «Способы идентификации», «Соответствия адресов контрагентов», вкладка «Продвинутые настройки», табличная часть «Товары». Откройте А и Б бок о бок и приведите Б к тем же значениям.

## Расписание

| Поле | Значение |
| --- | --- |
| Время начала | 00:00:00 |
| Время окончания | 23:59:59 |
| Повторять через | 300 сек |

## Шаги

1. Откройте настройки обмена БУС и создайте новую настройку Б (не копию А через «Подключить к БУС»).
2. Задайте параметры и реквизиты по таблицам выше, режим — «По расписанию», расписание — по таблице.
3. Сверьте с А формы из блока «Сверить с настройкой А рядом».
4. Сохраните и включите регламентное задание.
5. Настройку А оставьте без изменений.

> **Не нажимайте «Подключить к БУС»** ни для Б, ни для А: кнопка пересоздаёт подключение и сбрасывает действующие параметры обмена.

## Проверка

1. В логе nginx прода запросы идут каждые 5 минут:

   ```bash
   docker compose --env-file .env.prod -f docker/docker-compose.prod.yml logs nginx | grep "type=sale&mode=query"
   ```

2. Тестовый заказ получает отметку отправки за один интервал (≈5 минут):

   ```sql
   SELECT order_number, sent_to_1c, sent_to_1c_at
   FROM orders
   WHERE is_master = false
   ORDER BY created_at DESC LIMIT 5;
   ```

   Номер заказа сайта в 1С лежит в комментарии, сам документ БУС записывает под своим номером `СМУТ-…` (см. [диагностику](./order-import-handler-diagnostics.md)).

## Алерт о зависших заказах

Если 1С не забирает субзаказ дольше 30 минут, Celery-задача `alert_orders_stuck_in_1c` (раз в 10 минут) шлёт письмо со списком номеров и возрастом.

- Получатели — активные записи в «Получатели уведомлений» с флагом **«Сбои обмена с 1С»**; если таких нет, используется `ADMIN_EMAILS`. Нет ни тех, ни других — письма не будет, в лог пишется ошибка.
- Повторное письмо — при появлении нового зависшего заказа или через 6 часов, если набор не менялся. Когда зависших нет, состояние сбрасывается.
- В выборку не входят мастер-заказы, заказы с `export_skipped=True` и уже отправленные.
- Пороги: `ORDERS_STUCK_ALERT_THRESHOLD_MINUTES` (30) и `ORDERS_STUCK_ALERT_REPEAT_HOURS` (6) в `freesport/settings/base.py`.

## Откат

Отключите регламентное задание настройки Б (или удалите её). Настройка А продолжит выгружать каталог; заказы снова будут уходить только при ручном или плановом полном обмене, а алерт будет сообщать о задержке.
