# Этапы заказа из 1С на сайт: настройка выгрузки заказов БУС

Регламент для администратора 1С. После него клиент видит в кабинете, на странице заказа и в PDF этапы
«В обработке» → «Передан на склад» → «Отправлен» → «Доставлен», а также отмену заказа в 1С.

Спеки: `_bmad-output/implementation-artifacts/spec-1c-order-statuses-import.md` и
`spec-1c-order-statuses-followup.md` (таблица 1:1, лог, ограничения), исследование —
`research-1c-order-statuses.md` там же.

## Как это работает

1. В настройке обмена «По расписанию» (настройка Б из [регламента загрузки заказов](./orders-pull-schedule-setup.md))
   включается выгрузка заказов «только изменения».
2. БУС раз в 5 минут кладёт изменённые заказы в архив `v8_*.zip` и отправляет его на сайт:
   `type=sale&mode=file`, затем `type=sale&mode=import&filename=orders_<n>_<uuid>.xml`.
3. Сайт читает все `orders*.xml` этого обмена, находит субзаказ по `<Номер>` и `<Ид>` (`order-<pk>`),
   ставит статус по реквизиту «Статуса заказа ИД» и пересчитывает статус мастер-заказа.
   Импорт каталога при этом не запускается.

Этап берётся из **состояния заказа**, которое УТ вычисляет сама по резервам, отгрузкам и оплатам.
Менеджеру ничего вручную переключать не нужно.

Оплату из 1С сайт **не принимает**: даты оплаты и отгрузки, документы оплат и отгрузок игнорируются.

## Шаг 1. Выгрузка заказов в настройке Б

Карточка настройки Б → кнопка «Настроить» у блока синхронизации заказов (форма «Настройка обмена документами») →
блок «Настройка выгрузки документов»:

| Параметр | Значение |
| --- | --- |
| Выгружать заказы | Да |
| Выгружаются с | дата включения регламента (старые заказы выгружать незачем) |
| Только изменения (общие параметры настройки Б) | Да — уже включено по регламенту загрузки заказов |
| Выгружать отмененные товары | **Нет** — см. «Отмена заказа» ниже |
| Выгружать офлайн заказы | Нет — заказы, заведённые в самой 1С, сайту не нужны |
| Выгружать оплаты, Выгружать отгрузки | Нет |

Настройку А («В режиме реального времени») не трогайте: «Выгружать заказы» там остаётся выключенным.

## Шаг 2. Соответствия статусов

«Настроить соответствия статусов заказов» → форма «Сопоставление статусов», вкладка «Заказы».

Таблица соответствий — **1:1**: у каждого состояния УТ свой одноимённый Ид статуса сайта. Таблицу «много
состояний → один Ид» в этой форме не собрать: «Загрузить с сайта» даёт ровно одну строку на Ид, а кнопки
«Добавить», «Копировать», «Удалить» и перестановка строк в таблице отключены.

1. «Источник статусов заказов 1С» — **«Состояния заказов»**.
2. Нажмите **«Загрузить с сайта»** — колонка «Ид статуса» получит список статусов сайта (запрос `type=sale&mode=info`),
   по строке на Ид, в порядке ответа сайта. Первыми идут 10 состояний УТ из таблицы ниже, за ними — прежние Ид.
   **Признак релиза с таблицей 1:1** — в списке есть Ид «В процессе отгрузки». Его нет — релиз с таблицей 1:1
   на сайт не выкатан, дальше не продолжайте.
3. В колонке «Состояние» поставьте каждой из первых 10 строк одноимённое состояние:

| Ид статуса = Состояние заказа в УТ | Статус на сайте |
| --- | --- |
| Ожидается согласование | Новый (`pending`) |
| Ожидается оплата до обеспечения | В обработке (`processing`) |
| Готов к обеспечению | В обработке (`processing`) |
| Ожидается оплата до отгрузки | В обработке (`processing`) |
| Ожидается обеспечение | В обработке (`processing`) |
| Готов к отгрузке | Передан на склад (`at_warehouse`) |
| В процессе отгрузки | Передан на склад (`at_warehouse`) |
| Ожидается оплата | Отправлен (`shipped`) |
| Готов к закрытию | Отправлен (`shipped`) |
| Закрыт | Доставлен (`delivered`) |

4. **Очистите состояние** у строк с прежними Ид: «ОжидаетОбработки», «Подтвержден», «Отгружен», «Доставлен»,
   «Отменен», «Возвращен», «Не согласован», «На согласовании», «К выполнению», «Передан на склад».
   «Загрузить с сайта» переносит в них состояние из прежней таблицы (из первой строки с тем же Ид). Сами
   строки остаются пустыми — удалить их нельзя, выгрузке они не мешают. Строку «Закрыт» **не трогайте**: это
   и прежний, и новый Ид, её состояние — «Закрыт».
5. Поля **«Когда оплачен»**, **«Когда отгружен»**, **«Когда оплачен и отгружен»** оставьте **пустыми**.
   БУС проверяет их раньше таблицы: заполненное «Когда оплачен» с момента оплаты вытесняет этап, и
   «Передан на склад» сайт уже не увидит.
6. «Применить и закрыть» — **только когда у всех 10 новых строк проставлено состояние.** После «Загрузить
   с сайта» по старой таблице «много состояний → один Ид» у каждого прежнего Ид остаётся лишь первое из его
   состояний (`Form/Module.bsl:232–245`), остальные — например, «Ожидается обеспечение» — остаются без строки.
   Применить таблицу раньше — и заказы в таких состояниях уйдут на сайт без статуса (`no_status`), этап на
   сайте замрёт.

Почему важен порядок строк. При выгрузке заказа БУС ищет в таблице **первую** строку с состоянием заказа
(`БУС_ВыгрузкаСервер:8179`) и пишет её Ид в «Статуса заказа ИД». Новые Ид стоят первыми, поэтому даже
неочищенная строка с прежним Ид ниже не перехватит состояние — но очистка убирает двусмысленность.

Прежние Ид сайт по-прежнему понимает: заказы, выгруженные по старой таблице («К выполнению», «Передан на склад»,
«Отгружен»), получают тот же статус, что и раньше.

Статусы сайта двигаются только вперёд: состояние, откатившееся в 1С назад (например, из «Готов к отгрузке»
в «Ожидается обеспечение»), не возвращает статус сайта, а только записывается в поле «Статус 1С» карточки
заказа в админке.

### Перенастройка формы на `test_base` (владелец)

Узел «Загрузка заказов локально» настроен по старой таблице «много состояний → один Ид», записанной через
COM. Пересоберите её в форме, а не через COM:

1. Обновите локальный сайт до релиза с таблицей 1:1 (признак — Ид «В процессе отгрузки» в «Загрузить с сайта»),
   backend перезапущен.
2. Узел «Загрузка заказов локально» → «Настроить соответствия статусов заказов» → вкладка «Заказы».
3. «Загрузить с сайта» → проверьте, что первые 10 строк — состояния УТ из таблицы выше, начиная с
   «Ожидается согласование», и есть «В процессе отгрузки».
4. Выполните пункты 3–4 раздела «Шаг 2. Соответствия статусов» и, только когда все 10 новых строк заполнены,
   нажмите «Применить и закрыть».
5. Измените в 1С любой заказ с сайта (например, перепроведите его) и дождитесь обмена.
6. В копии файла в `EXCHANGE_LOG_DIR` реквизит «Статуса заказа ИД» равен состоянию заказа (новый Ид),
   в логе backend есть строка `[BUS ORDERS] … updated=1`.

## Шаг 3. Номер заказа сайта

«Настроить реквизиты загружаемых в 1С документов» → «Заказ клиента»: строка **«Номер по данным клиента»** —
«Предопределенный алгоритм», значение **«Номер с сайта»** (значение БУС по умолчанию). Из этого реквизита БУС
пишет `<Номер>` при выгрузке; по нему и по `<Ид>` сайт находит заказ. Другое значение — и заказ не найдётся
или упадёт в конфликт номера.

## Отмена заказа

Сайт ставит «Отменён», если в документе реквизит `Отменен` = `true` и при этом:

- в документе нет строк товаров (строка доставки не в счёт) — все строки отменены в 1С, или
- заказ помечен на удаление.

Галка «Выгружать отмененные товары» должна быть **выключена**. Если её включить, БУС выгружает отменённые
строки и ставит `Отменен` = `true` любому заказу, где отменена хоть одна строка. Сайт такой отмене не верит:
пишет предупреждение в лог, статус берёт по таблице, но **в финальный статус не переводит**. Так «Закрыт»
у частично отменённого заказа не превращается в «Доставлен», а в «Статус 1С» записывается фактическое значение.

## Ограничения УТ и БУС

- **Заказ с сайта не выгружается до первой правки в 1С.** Заказ, загруженный с сайта, БУС к выгрузке не
  регистрирует (`ЗагрузкаСБУС`, `БУС_РегистрацияИзмененийВызовСервера:108`). Пока менеджер не изменит
  заказ в 1С (не поставит резерв, не перепроведёт), сайт показывает «Новый».
- **«Закрыт» — только при полной оплате или отменённых строках.** Отгруженный, но не оплаченный полностью
  заказ стоит в «Ожидается оплата» (на сайте — «Отправлен») и до «Доставлен» не дойдёт.
- **Резерв — только со складом в строках.** Без склада в строке резерв не ставится, и заказ не дойдёт
  до «Готов к отгрузке» — на сайте останется «В обработке».
- **Ордерный склад сразу даёт «В процессе отгрузки».** На складе с ордерной схемой резерв «Отгрузить»
  переводит заказ в «В процессе отгрузки», минуя «Готов к отгрузке». Статус сайта тот же — «Передан на склад».
- **Отмена всех строк.** УТ ставит такому заказу «Готов к закрытию» (по таблице — «Отправлен»), но в
  выгрузке `Отменен` = `true` и строк нет — сайт ставит «Отменён» (см. «Отмена заказа»).

## Бонусы тренерам

Бонус начисляется, когда мастер-заказ переходит **ровно** в статус «Статус заказа для начисления» из настроек
бонусной программы (по умолчанию «Доставлен»). Заказ может перескочить промежуточный статус: например, из
«Передан на склад» сразу в «Доставлен», если между выгрузками заказ отгрузили и закрыли. Поэтому статусом
начисления держите «Доставлен», а не «Отправлен» или «Передан на склад».

## Проверка

1. В логе nginx прода раз в 5 минут, когда в 1С есть изменённые заказы, идут загрузки заказов:

   ```bash
   docker compose --env-file .env.prod -f docker/docker-compose.prod.yml logs nginx | grep "type=sale&mode=import&filename=orders"
   ```

   Ответ сайта на такой запрос — `success`. `failure` бывает, только если XML не дошёл, битый или старше
   суток, либо при сбое БД; тогда БУС оставляет пакет и повторяет его при следующем запуске.

2. В логе backend — строка с итогами по каждому файлу, со временем и уровнем:

   ```bash
   docker compose --env-file .env.prod -f docker/docker-compose.prod.yml logs backend | grep "\[BUS ORDERS\]"
   ```

   Строки `[BUS ORDERS]` (и `[INFO MODE]` на «Загрузить с сайта») есть **начиная с релиза с таблицей 1:1**
   (признак — Ид «В процессе отгрузки» в «Загрузить с сайта»): раньше логгер `apps.integrations` не был
   настроен, и INFO-строки отбрасывались.

   `not_found` — заказы без пары на сайте (например, заведённые в 1С вручную), это штатно.
   `no_status` — у состояния заказа нет строки в таблице соответствий.

3. Копия каждого принятого файла лежит в каталоге журналов обмена (`EXCHANGE_LOG_DIR`, по умолчанию
   `backend/var/1c_exchange/logs/`).

4. Контрольный заказ: проведите заказ с сайта до «Готов к отгрузке» — в кабинете клиента он станет
   «Передан на склад» за один интервал обмена.

## Откат

- **Выключить выгрузку.** В настройке Б снимите «Выгружать заказы». Статусы на сайте останутся последними
  полученными; новые этапы перестанут приходить.
- **Откатить сайт ниже релиза с таблицей 1:1** (признак — Ид «В процессе отгрузки» в «Загрузить с сайта»).
  Прежний сайт новых Ид не знает: заказы с ними он пропустит как неизвестный статус, этапы замрут. Поэтому
  **до** отката сайта пересоберите таблицу формы на прежние Ид — перенесите состояния со строк новых Ид на
  строки прежних — или очистите состояния у новых строк.

## Тестовые данные

Реальная выгрузка `orders_*.xml` с `test_base` кладётся в `backend/data/import_1c/orders/` и прогоняется
тестом `tests/integration/test_orders_bus_import.py::test_bus_orders_real_export` (`data_dependent`).
Снять её: на `test_base` провести 3–4 заказа с сайта до «Готов к отгрузке» и «Закрыт», один отменить,
в настройке «Обмен локальный» включить выгрузку заказов в каталог с источником «Состояния заказов» и
таблицей из шага 2, запустить обмен. В приватный репозиторий `FREESPORT-1c-test-data` (каталог `orders/`)
файл добавляется по команде владельца.
