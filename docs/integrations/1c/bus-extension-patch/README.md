# Правка расширения БУС: вид цен клиента в выгрузке контрагентов

Часть A задания `_bmad-output/implementation-artifacts/tasks/dev-task-role-from-1c-agreement.md`.

Выгрузку `contragents_*.xml` формирует **тиражное расширение
`ОбменСБитриксУправлениеСайтомУТ`** («Интернет-магазин + «1С»» от 1С-Битрикс), а не типовой
модуль `ОбменССайтом` и не самописная обработка. Установка новой версии модуля (загрузка `.cfe`
поверх) заменяет и общий модуль, и XSD-макет — правки теряются **молча**: файлы продолжают
приходить, но без блока `<ЗначенияРеквизитов>`, и роли на портале перестают обновляться.

Этот каталог — копия правок, чтобы их можно было наложить заново.

> ✅ **Актуальна вторая редакция** (реквизит `СоглашениеСтатус` = `НетСоглашения`, решение
> от 2026-08-02). Наложена и проверена на `test_base` **2026-08-04**: блок
> `<ЗначенияРеквизитов>` приходит у каждого контрагента, контрагентов без блока ноль.
> Постановка — `_bmad-output/implementation-artifacts/tasks/dev-task-bus-agreement-status.md`.
> **На прод не переносилась.** Первую редакцию на прод не переносить: портал (эпик 40)
> рассчитан на вторую.

## Что правится

| Объект расширения | Что добавлено |
|---|---|
| макет `Справочник.БУС_НастройкиОбмена.СхемаXSDОбмена` | элемент `ЗначенияРеквизитов` в тип `Контрагент` — без него XDTO не даёт записать блок |
| `ОбщийМодуль.БУС_ВыгрузкаСервер`, `СформироватьДанныеПоКонтрагентам` | отбор действующих соглашений с видом цен (формула A2) и запись четвёрки реквизитов |

Все вставки помечены маркером `FREESPORT: вид цен клиента`.

## Что попадает в XML

```xml
<ЗначенияРеквизитов>
  <ЗначениеРеквизита>
    <Наименование>ТипЦенId</Наименование>
    <Значение>a91bdb02-b3f2-11ea-81c3-00155d3cae02</Значение>
  </ЗначениеРеквизита>
  <ЗначениеРеквизита>
    <Наименование>ТипЦенНаименование</Наименование>
    <Значение>Опт 2 (150-300 тыс.руб в квартал)</Значение>
  </ЗначениеРеквизита>
  <ЗначениеРеквизита>
    <Наименование>СоглашениеНаименование</Наименование>
    <Значение>Опт 2</Значение>
  </ЗначениеРеквизита>
  <ЗначениеРеквизита>
    <Наименование>СоглашениеТиповое</Наименование>
    <Значение>true</Значение>
  </ЗначениеРеквизита>
</ЗначенияРеквизитов>
```

Нет подходящих соглашений или вид цен ни у одного из них не заполнен — блок выгружается всё
равно, с единственным реквизитом:

```xml
<ЗначенияРеквизитов>
  <ЗначениеРеквизита>
    <Наименование>СоглашениеСтатус</Наименование>
    <Значение>НетСоглашения</Значение>
  </ЗначениеРеквизита>
</ЗначенияРеквизитов>
```

Благодаря этому блок приходит у **каждого** контрагента, и «нет соглашения» перестаёт быть
неотличимым от «патч затёрт обновлением модуля БУС». Отсутствие блока означает ровно одно —
правка в расширении потеряна.

Подходящих соглашений несколько — каждое даёт свою четвёрку реквизитов (на маркетплейсах один
и тот же `ТипЦенId` приходит дважды: «Выкуп …» и «Комиссионное …»; парсер портала обязан
дедуплицировать GUID).

`ТипЦенId` — `Строка(ВидЦен.УникальныйИдентификатор())`, остальные три реквизита нужны только
для диагностики, портал по ним решений не принимает. `СоглашениеТиповое` приходит как
`true` / `false`. `СоглашениеСтатус` пишется **только** при отсутствии видов цен и никогда не
соседствует с `ТипЦенId`; пустой `ТипЦенId` не выгружается — у такого контрагента GUID
отсутствует, а не пуст.

## Отбор соглашений

```
НЕ Соглашение.ПометкаУдаления
И Соглашение.Статус = Перечисление.СтатусыСоглашенийСКлиентами.Действует
И (ДатаНачалаДействия    = пустая дата ИЛИ ДатаНачалаДействия    <= ТекущаяДата)
И (ДатаОкончанияДействия = пустая дата ИЛИ ДатаОкончанияДействия >= ТекущаяДата)
И ЗначениеЗаполнено(Соглашение.ВидЦен)
И Соглашение.ВариантРасчетаЦен содержит «вид цен в шапке»
И (
     Соглашение.Партнер = &Партнер
  ИЛИ Соглашение.СегментПартнеров В (ВЫБРАТЬ Сегмент ИЗ РегистрСведений.ПартнерыСегмента
                                     ГДЕ Партнер = &Партнер)
)
```

Два условия типового запроса `СамообслуживаниеСервер` в отбор **не включены**:

1. `И Соглашение.ДоступноВнешнимПользователям` — флаг снят у всех 295 действующих соглашений,
   выгрузка вернула бы ноль строк;
2. `ИЛИ Типовое И СегментПартнеров = ПустаяСсылка` — притянуло бы `Акция МАРТ` и `РАСПРОДАЖА`
   (вид цен `Опт 1`) каждому партнёру, все стали бы неоднозначными.

Реализовано тремя временными таблицами в пакете запроса `СформироватьДанныеПоКонтрагентам`:

| Таблица | Что содержит |
|---|---|
| `ВТ_FS_СегментыПартнеров` | регистр `ПартнерыСегмента` по партнёрам выгружаемых контрагентов |
| `ВТ_FS_ДействующиеСоглашения` | отбор по формуле; восемь значений перечисления `ВариантыРасчетаЦенПоСоглашениямСКлиентами`, содержащих «ВидЦенВШапке» |
| `ВТ_FS_ВидыЦенКонтрагентов` | объединение индивидуальных и сегментных соглашений |

Границы дат сравниваются с `НачалоДня(ТекущаяДатаСеанса())`; пустой партнёр и пустой сегмент
из соединений исключены явно.

## Правила заполнения

- Соглашений нет или вид цен не заполнен → блок выгружается со статусом `НетСоглашения`.
  Пустой `ТипЦенId` не отправляется.
- XDTO-объект блока создаётся до проверки пустоты выборки и присваивается контрагенту
  безусловно — пустым блок быть не может.
- Вид цен выгружается при каждой выгрузке контрагента. Контроль изменений задаётся флагом
  «Полная выгрузка» / «Выгружать только изменённые объекты» в карточке настройки обмена
  (реквизит `ВыгружатьТолькоИзменения`, попадает в XML как `СодержитТолькоИзменения`).
  При выгрузке только изменений смена соглашения, смена сегмента партнёра и пересчёт
  динамического сегмента обязаны помечать контрагента изменённым — иначе новый уровень не
  доедет до портала.
- Отбор контрагентов задаётся СКД в форме «Настройка выгрузки контрагентов». В настройках
  схемы по умолчанию лежит **активный** элемент отбора `Контрагенты` / `Равно` с незаданным
  значением — он отбирает ноль строк, и выгрузка контрагентов молча даёт пустой результат.
  Галку с этого элемента нужно снять, после чего нажать «Применить»: до первого «Применить»
  ключ `НастройкиВыгрузкиКонтрагентов` в `СохраненныеНастройки` отсутствует, а
  `СформироватьДанныеПоКонтрагентам` в этом случае выходит по `Возврат` без ошибки и без файлов.

## Как применить

Оба скрипта идемпотентны: повторный запуск ничего не меняет, рядом с изменяемым файлом
кладётся `.orig`.

```bash
# 1. выгрузить исходники расширения из базы
1cv8.exe DESIGNER /S"<сервер>\<база>" /N"<пользователь>" /P"<пароль>" \
    /DumpConfigToFiles "<каталог>" -Extension "ОбменСБитриксУправлениеСайтомУТ" -force

# 2. наложить правки
python patch_xsd_contragent.py          # путь к макету задан внутри скрипта, поправьте под себя
python patch_bus_module.py <каталог>

# 3. залить обратно пообъектно (полная загрузка не работает — платформа падает
#    на командах форм LevelDown / LevelUp / List)
1cv8.exe DESIGNER /S"<сервер>\<база>" /N"<пользователь>" /P"<пароль>" \
    /LoadConfigFromFiles "<каталог>" -Extension "ОбменСБитриксУправлениеСайтомУТ" \
    -files "Catalogs\БУС_НастройкиОбмена.xml" -updateConfigDumpInfo /UpdateDBCfg
# и то же самое с -files "CommonModules\БУС_ВыгрузкаСервер.xml"
```

Ограничения, на которые уходит время, если про них не знать:

- **только пообъектная загрузка** — полная `/LoadConfigFromFiles` падает на командах форм
  `LevelDown` / `LevelUp` / `List`;
- **конфигуратор из bash не стартует** — запускать через PowerShell-launcher со `Start-Process`
  (готовые лежат в `C:\Users\1\DEV\1C-PROJECT`: `dump-ext.ps1`, `load-ext-module.ps1`,
  `load-ext-partial.ps1`, `check-ext-syntax.ps1`, `restore-ext-8140.ps1`, `verify-xsd-in-db.ps1`);
- **версия платформы** должна совпадать с серверной (на 2026-08-01 — 8.3.27.2130), иначе
  конфигуратор выходит с «Несоответствие версий клиента и сервера»;
- `/CheckConfig -Extension ... -Server` штатно выдаёт ~60 предсуществующих ошибок по
  `Обработка.DataMobileLoad` — вывод фильтровать по имени своего модуля;
- откат: `ext-src\ОбменСБитриксУправлениеСайтомУТ_8.1.0.40_test_base.cfe` (`restore-ext-8140.ps1`).

## Проверено на

| Контур | Версии |
|---|---|
| тест `127.0.0.1\test_base` | УТ 11.5.22.134 + БУС 8.1.0.40, платформа 8.3.27.2130 |
| прод | УТ 11.5.27.49 + БУС 8.1.0.45 |

Целевые функции в 8.1.0.40 и 8.1.0.45 идентичны побайтово, поэтому правка с теста валидна для
прода. Само расширение 8.1.0.45 на тест не встаёт: заимствует `РегистрСведений.ДоступныеОстаткиТоваров`,
которого в УТ 11.5.22.134 нет.
